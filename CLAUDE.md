# Проект: Магистерская диссертация — Беспилотный сельскохозяйственный трактор

## Тема работы
«Система обработки сенсорных данных для поддержки принятия решений в беспилотных (сельскохозяйственных) транспортных средствах»

Работа пишется на русском языке, объём 90–100 страниц. Разработка ведётся как практическая часть (Глава 4) диссертации.

### Важное следствие из характеристик GPU/VRAM
**Gazebo запускается ТОЛЬКО в headless режиме** (без GUI сервера Gazebo Classic `gzclient`, только `gzserver`). Рендеринг физического симулятора невозможен — не хватит видеопамяти и нет 3D ускорения. Визуализация сцены — через **RViz2**, который работает с программным рендерингом и легче.

**Это означает на практике:**
- В launch-файлах Gazebo всегда передаём параметр `gui:=false`
- Для проверки того, что происходит в симуляции — используем RViz2 (отображение odometry, TF, лидара, карты)
- Для отладки миров Gazebo можно временно включать gzclient, но долго работать с ним нельзя — VM зависает

### Синхронизация файлов Windows ↔ Ubuntu
- **Папка на Windows:** `D:\ROS2_Project` — здесь работает Claude Code
- **Та же папка в Ubuntu:** `~/shared` (т.е. `/home/dan/shared`) — автомонтируется через `/etc/fstab`
- **Имя общего ресурса в VirtualBox:** `ros2_project`
- **Guest Additions:** установлены (7.1.8)

**Весь код проекта лежит в `D:\ROS2_Project` (= `~/shared` в Ubuntu).** Claude Code редактирует файлы на Windows, в Ubuntu они появляются мгновенно. Сборка (`colcon build`) выполняется в Ubuntu.

## Структура ROS 2 пакетов (план Главы 4)

Пакеты создаются в `~/shared/` (= `D:\ROS2_Project\`) в подпапке `src/`, затем при сборке в Ubuntu они должны быть доступны из `~/ros2_ws/src/` — через symlink или прямое размещение. Архитектура выбирается при создании первого пакета.

Пакеты, которые должны быть разработаны:

1. **`agv_description`** — URDF/Xacro модель трактора, визуальные и коллизионные меши, joints, links
2. **`agv_gazebo`** — миры Gazebo (модель сельхоз поля), модели препятствий, плагины сенсоров
3. **`agv_sensor_processing`** — узлы обработки сенсоров (sensor_fusion через robot_localization EKF, lidar_processing, camera_processing)
4. **`agv_navigation`** — глобальный планировщик, локальный планировщик, интеграция с Nav2, алгоритм покрытия территории (Coverage Path Planning)
5. **`agv_decision`** — конечный автомат состояний, логика принятия решений, обработка аварийных ситуаций
6. **`agv_visualization`** — конфигурации RViz2, панель мониторинга
7. **`agv_bringup`** — launch-файлы для запуска всей системы

## Рекомендации по разработке с учётом ограничений ресурсов

### При запуске Gazebo
- Всегда `gui:=false` (headless)
- Использовать простую физику без тяжёлых meshes — низкополигональные модели
- Упрощённая модель поля: плоская поверхность с текстурой, не сложный terrain
- Ограничить частоту публикации сенсоров: Lidar ≤ 10 Hz, камера ≤ 5 Hz, IMU ≤ 50 Hz
- Во время разработки — минимум препятствий в мире (2–5 объектов)

### При запуске RViz2
- Отключать неиспользуемые отображения (PointCloud иногда тяжёлый)
- Fixed Frame выбирать корректно (`odom` или `map`)

### Производительность
- Не запускать одновременно Gazebo + RViz2 + VS Code с большим проектом — VM начнёт свопиться
- Для тестов — сначала Gazebo headless, потом RViz2 отдельно
- Следить за загрузкой памяти: `htop` или `free -h`

### При написании кода
- Python предпочтительнее C++ (проще отлаживать, не нужна сборка `colcon build` после каждой правки узла — `colcon build --symlink-install` вместо этого)
- Узлы делать лёгкими, асинхронная обработка
- Логирование умеренное — `rosbag2` быстро съест диск

## Команды, которые часто понадобятся

Работа ведётся с двух сторон:

**На Windows (здесь, в Claude Code):**
- Редактирование файлов в `D:\ROS2_Project\`
- Git операции

**В Ubuntu (отдельный терминал VM):**
- `cd ~/shared` — перейти в общую папку
- `cd ~/ros2_ws && colcon build --symlink-install` — собрать пакеты
- `source ~/ros2_ws/install/setup.bash` — применить изменения
- `ros2 launch <package> <launchfile>` — запустить систему
- `htop` — следить за памятью/CPU
- `free -h` — проверить свободную RAM
