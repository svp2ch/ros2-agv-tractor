# Описание программной системы беспилотного трактора

Система реализована на **ROS 2 Humble** и состоит из **7 пакетов** (модулей),
каждый отвечает за свой слой: от модели машины и симуляции до обработки
сенсоров, навигации и принятия решений. Ниже — назначение каждого пакета,
ключевые файлы и поток данных между ними.

---

## 1. Архитектура: 7 пакетов

### 1.1. `agv_description` — геометрическая модель трактора
Описывает, как трактор устроен физически (звенья, сочленения, сенсоры).
- `urdf/tractor.urdf.xacro` — URDF/Xacro-модель: корпус, 4 колеса, кабина,
  крепления GPS, IMU, 2D-лидара, камеры. Задаёт размеры, массы, инерцию.
- `launch/display.launch.py` — просмотр модели в RViz без симуляции.

### 1.2. `agv_gazebo` — симуляция (мир + физика + сенсоры)
Запускает виртуальное поле и «оживляет» сенсоры трактора.
- `worlds/agricultural_field.world` — плоское с/х поле 36×36 м, столбы-препятствия,
  настройки физики ODE, **географическая привязка GPS** (`spherical_coordinates`).
- `urdf/tractor.gazebo.xacro` — Gazebo-плагины: привод колёс (skid-steer),
  плагины GPS, IMU, 2D-лидара (ray sensor), RGB-камеры — с моделями шума.
- `launch/gazebo.launch.py` — старт Gazebo (headless) + спавн трактора.

### 1.3. `agv_sensor_processing` — слияние сенсорных данных (ядро темы)
Превращает «сырые» данные сенсоров в надёжную оценку положения.
- `config/ekf_local.yaml` — **локальный EKF** (robot_localization): сливает
  колёсную одометрию + IMU → плавная одометрия в системе `odom` (TF odom→base_link).
- `config/navsat_transform.yaml` — **navsat_transform**: переводит GPS
  (широта/долгота) в декартовы координаты карты `map`.
- `config/ekf_global.yaml` — **глобальный EKF**: сливает одометрию + IMU + GPS →
  положение на поле и коррекция дрейфа (TF map→odom).
- `agv_sensor_processing/lidar_processing.py` — фильтрация скана лидара.
- `agv_sensor_processing/sensor_fusion.py` — узел-монитор качества слияния.

### 1.4. `agv_navigation` — планирование и движение
Строит маршрут покрытия поля и ведёт по нему трактор.
- `agv_navigation/coverage_planner.py` — **планировщик покрытия** (бустрофедон,
  «змейка»): разбивает поле на полосы и строит маршрут из 34 точек.
- `config/nav2_params.yaml` — параметры **Nav2**: глобальный планировщик,
  локальный планировщик DWB, costmap'ы (карты препятствий), скорости, допуски.
- `launch/navigation.launch.py` — запуск стека Nav2 (+ опционально SLAM).
- `agv_navigation/nav_client.py` — вспомогательный клиент навигации.

### 1.5. `agv_decision` — принятие решений (конечный автомат)
«Мозг» трактора: следит за обстановкой и переключает режимы.
- `agv_decision/decision_node.py` — **FSM** (конечный автомат состояний):
  IDLE → NAVIGATING → AVOIDING_OBSTACLE / TURNING → … → EMERGENCY_STOP /
  TASK_COMPLETE. Берёт точки маршрута по очереди и отправляет их в Nav2,
  тормозит при аварийном сближении с препятствием, копит пройденную траекторию.

### 1.6. `agv_visualization` — визуализация
- `config/agv_rviz.rviz` — конфигурация RViz2: модель, лидар, одометрия,
  маршрут покрытия, пройденная траектория, границы поля, статус FSM.

### 1.7. `agv_bringup` — единый запуск
- `launch/full_system.launch.py` — запускает всю систему по таймерам:
  Gazebo (t=0) → сенсоры/EKF (t=8) → навигация (t=15) → FSM (t=20) → RViz (t=22).

## 2. Поток данных (как всё работает вместе)

```
        ┌─────────────── Gazebo (симуляция поля и трактора) ───────────────┐
        │   /odom (колёса)   /imu/data   /gps/fix   /scan (лидар)          │
        └────────┬──────────────┬───────────┬───────────┬─────────────────┘
                 │              │           │           │
                 ▼              ▼           ▼           ▼
     ┌─────────────────── agv_sensor_processing ───────────────────┐
     │  ekf_local (odom+IMU) → TF odom→base_link                   │
     │  navsat_transform (GPS→map) → /odometry/gps                 │
     │  ekf_global (odom+IMU+GPS) → TF map→odom, /odometry/filtered_map │
     └───────────────────────────┬─────────────────────────────────┘
                                 │ (надёжное положение на поле)
            ┌────────────────────┼─────────────────────┐
            ▼                                          ▼
  ┌──── agv_navigation ────┐               ┌──── agv_decision (FSM) ────┐
  │ coverage_planner:      │  /coverage_path │ берёт точки по очереди,    │
  │ строит «змейку» 34 точки├───────────────►│ шлёт в Nav2, следит за     │
  │ Nav2: ведёт к точке,   │◄──────────────┤ препятствиями (/scan),      │
  │ объезжает препятствия   │  navigate_to_pose│ аварийный стоп            │
  └───────────┬────────────┘               └────────────────────────────┘
              │ /cmd_vel (скорости)
              ▼
        Gazebo (трактор едет) ──► RViz2 (визуализация)
```

Кратко: **сенсоры → слияние (EKF) → точное положение → планировщик строит
маршрут → Nav2 ведёт по нему и объезжает препятствия → FSM контролирует логику
и безопасность → команды скорости возвращаются в трактор.**

## 3. Что изменено относительно старой версии программы

Старая версия запускалась, но трактор вёл себя неправильно. Исправлено:

**A. Шасси и движение (Gazebo).**
- Исправлена ось колёс (команда «вперёд» гнала трактор назад).
- Настроен поворот skid-steer: передние колёса скользят вбок, увеличены
  момент и ускорение привода — трактор стал реально разворачиваться.
- Лидар поднят и его мин. дальность 0.4→0.7 м — устранена «самозасветка»
  (трактор видел сам себя как кольцо фантомных препятствий).

**B. Логика маршрута (FSM).**
- Устранён сброс прогресса: планировщик каждые 5 с переотправлял маршрут, и
  индекс текущей точки обнулялся — трактор бесконечно возвращался к точке 1
  («носился по полю»). Теперь прогресс сохраняется.

**C. Локализация — переход со SLAM на GPS-слияние (ключевое изменение).**
Старая версия полагалась на SLAM, но на ровном безпризнаковом поле он не
работает (лидару не за что зацепиться) — карта уезжала на десятки метров, и
трактор «достигал» точек лишь в воображаемых координатах. Переведено на
слияние **GPS + IMU + одометрия** через robot_localization (это и есть тема
работы — обработка сенсорных данных). Исправлена цепочка дефектов: задана
география мира, зафиксирована точка отсчёта GPS, исправлены ремаппинги и
система координат GPS-измерений. Результат: коррекция карты <1 м, трактор
реально едет по полю и проходит маршрут.

**D. Скорость и качество хода.**
- Максимальная скорость снижена 2.5→1.0 м/с (реалистично для трактора, ход
  ровнее, нагрузка на симуляцию ниже).

**Итог:** трактор корректно локализуется по GPS-слиянию, строит маршрут-змейку
по всему полю, последовательно проходит точки и объезжает препятствия.
